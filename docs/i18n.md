# Localization

Supported locales: `en` (default), `ko`, `ja`, `zh` (Simplified).

## How it works
- Dictionaries live in `src/i18n/<locale>.ts`, all typed against the English dictionary so a missing
  key is a compile error.
- `I18nProvider` (in `src/i18n/index.tsx`) holds the current locale; `useT()` returns `t(key, vars?)`
  and the active locale. `{name}` placeholders are replaced from `vars`.
- Locale is persisted to `localStorage("aeo-locale")`; the default comes from `navigator.language`.
- `LocaleSwitch` in the header cycles/selects locales.

## Register
Page leads end on a noun, not on an adverbial. Korean "실시간으로." and Japanese "リアルタイムで。"
read as a sentence cut off mid-way; "실시간으로 확인." and "リアルタイムで確認。" close it while staying
in the same clipped register as the other leads, which end on plain nouns.

## Rules
- No literal user-facing strings in components. Add a key to `en.ts`, then translate in the other three.
- Keep keys namespaced by feature: `header.*`, `mp.*`, `reg.*`, `pay.*`, `common.*`.
- Numbers, currency, and relative time use `Intl` with the active locale (`lib/format.ts` takes a locale).
- Data from external sources (agent names, descriptions) is shown as-is and never translated.
