# Code audit, 2026-09-05

Produced by `codex exec` against the whole tree, then triaged. The status column records what was
actually done; a deferred item is a deliberate decision, not an oversight.

| Finding | Status |

| Reverted USDC calls counted as payments | Fixed. Each scan first reads USDC `Transfer` logs for the range and only accepts candidates whose transaction actually emitted one. |

| Overlapping scans from `setInterval` | Fixed. Both pollers are single-flight. |
| Unbounded catch-up after a hidden tab | Fixed. Payments cap the catch-up at 60 blocks; the registry caps each read at the chain's log range. |
| No D3 cleanup on unmount | Fixed. Routes unmount the graph, so the simulation is stopped and transitions interrupted. |
| Link weights never reset | Fixed. Node and link weights both reset before re-counting the window. |
| Nodes keyed by address only, role overwritten | Fixed. Nodes are keyed `role:address`. |
| Only 12 events got real timestamps | Fixed. Timestamps are estimated from block distance for every event, so ordering and relative time hold across the whole range. |

| API responses never validated | Fixed. Aggregate and snapshot responses are normalized at the query boundary. |

## Original findings

## High

- `src/features/payments/usePayments.ts:70-83` — severity: high — every transaction sent to USDC with one of the four EIP-3009 selectors is counted as a payment without checking the receipt. A reverted authorization still enters `found`, increments `counts`, and contributes to the displayed count and volume. Fetch the receipt for each candidate and require `status === 'success'` plus a matching USDC `Transfer` log before committing it.

- `src/features/registry/useRegistry.ts:80-91,97-104` — severity: high — an initial per-chain RPC failure is swallowed, leaving that chain's cursor undefined. The query still returns `true`, so polling starts, but `from == null` makes that chain skip every tick; with `staleTime: Infinity` it never retries until the hook is remounted. Keep failed chains pending and retry their initial bounded range (or let the query retry) before marking initialization complete.

## Medium

- `src/features/payments/usePayments.ts:95-108` and `src/features/registry/useRegistry.ts:100-115` — severity: medium — `setInterval` starts another async scan while the previous one is still in flight, and the initial payment scan also runs alongside the interval. Both scans can read the same cursor; an older completion can write a cursor behind a newer completion, causing duplicate RPC work and rescans. Payment `blocksScanned` and `senderCounts` are incremented again even when state dedupes the rows. Use a single-flight loop/lock and ignore all stale completions after cleanup, including the first StrictMode effect.

- `src/features/payments/usePayments.ts:63-68,98-103` and `src/features/registry/useRegistry.ts:101-109` — severity: medium — catch-up ranges are not bounded. After a hidden tab, offline period, or slow RPC, payments materializes every block number and full block result between the old cursor and the new head, while registry passes the entire gap to `getLogs` without applying `CHAINS[c].logRange`. The payment scan can freeze or consume large memory; the registry RPC can reject an over-limit range and then retry the same gap forever. Process bounded chunks and commit the cursor per successful chunk, with an explicit gap policy.

- `src/features/payments/PaymentGraph.tsx:63-77,120-147` — severity: medium — the force simulation and D3 transitions have no unmount cleanup. The current route switch unmounts `PaymentGraph`, but `sim.current` keeps its timer and tick closure alive; particle, node, and link transitions also continue against detached SVG nodes. Stop the simulation, remove its tick listener, and interrupt/remove active SVG transitions in effect cleanup.

- `src/features/payments/PaymentGraph.tsx:48,51-58,84` — severity: medium — node weights are reset before being recomputed, but link weights are never reset. Every graph effect increments existing links, including effects caused by a successful poll with no new payment because `usePayments` creates new state arrays. Edge widths quickly stop representing the recent window, and `Link.weight` grows without bound. Reset each kept link weight before accumulation or derive the link map afresh.

- `src/features/payments/PaymentGraph.tsx:43-54,59,135-145` — severity: medium — nodes are keyed only by address even though the same address can occupy payer, facilitator, and payTo roles. `up` reuses the node and the last call overwrites its `kind`, so colors, force strengths, labels, weights, and particle endpoints become wrong (and a self-loop is possible). Key nodes and links by a role-qualified ID, or model role as part of the node identity.

- `src/features/registry/useRegistry.ts:18-27,43-51,65-70` — severity: medium — all fetched logs initially receive `Date.now()`, but `stampTimes` only fetches timestamps for the first 12 event entries. Older events retain the observation time, then `merge` sorts by that timestamp before block number; a large initial range therefore displays old rows as `0s` and can order cross-chain rows by unrelated block heights. Stamp every displayed event (or preserve an explicit unknown/approximate timestamp and sort known block times correctly).

- `src/features/registry/useRegistry.ts:20-37` and `src/features/registry/RegistryLog.tsx:47-56` — severity: medium — `parseAgentURI` returns `unknown` fields, but the hook casts `name` and `description` to strings and renders them directly. A valid on-chain `data:` JSON document containing an object for `description` or `name` can make React throw while rendering the log. Validate field types at the parsing boundary and discard/coerce invalid metadata.

- `src/features/marketplaces/useAggregates.ts:11-30`, `src/features/overview/OverviewPanel.tsx:18-23`, and `src/features/marketplaces/MarketplacesPanel.tsx:23-67` — severity: medium — the generic arguments to `useQuery` are compile-time assertions only; fetched JSON is never validated. A status-200 schema error or missing `daily`, `x402`, `erc8004Registry`, or snapshot `items` field causes render-time dereferences such as `.map`/`.length` to throw instead of producing a query error or partial fallback. Parse and normalize each response before exposing it to components.

- `src/data/chains.ts:19-32` and `src/lib/clients.ts:6-14` — severity: medium — Base and BNB each configure only one RPC URL, so wrapping `cfg.rpcs` in `fallback()` does not provide failover for either chain. A single public endpoint outage takes that live feed down. Add a vetted secondary endpoint for each chain or expose the lack of fallback in the UI/configuration.

- `src/features/payments/usePayments.ts:27,81-83` and `src/features/payments/PaymentsPanel.tsx:16-20,36-38` — severity: medium — the uint256 USDC amount is converted from `bigint` to `number` before storage and summation. Values above the IEEE-754 safe integer range in raw micro-USDC units lose cents/micro-units, so the payment volume is not exact. Retain the raw bigint/decimal string and sum with bigint or a decimal representation; convert only for display.

- `src/features/payments/usePayments.ts:42-45,90-93` and `src/features/overview/OverviewPanel.tsx:39-41` — severity: medium — `paymentsPerMinute` divides the cumulative `blocksScanned` by `payments.length`, but `payments` is truncated to the last 300 entries. Once older payments are evicted, the numerator still covers their elapsed scan time while the denominator does not, so the observed rate decays toward zero even if recent activity is steady. Compute both values over the same rolling window or maintain an untruncated count for the full denominator.

- `src/features/payments/usePayments.ts:56-57,76-77,90-93` — severity: medium — `counts.current` retains one counter for every facilitator address ever seen, while the payment rows are capped at 300. A long-lived page with many distinct senders grows the map and the copied `senderCounts` state without bound, and counts include rows that have already been evicted. Derive counts from the bounded window or use a bounded/top-N counter with explicit eviction.

- `scripts/snapshot.mjs:59-62` and `src/features/marketplaces/MarketplacesPanel.tsx:24-26` — severity: medium — when the agentscan `/stats` request fails, the script writes `stats: null` but `write` sets `total` to the fetched page length (100). The card then falls back to `snap.data.total` and reports `100` as the total indexed agents instead of showing unavailable data or retaining a real total. Persist `j.total` separately and never use page length as the global fallback.

- `scripts/snapshot.mjs:12-20` — severity: medium — snapshot requests have no timeout and retry only HTTP 429. A hung request can consume the workflow's entire 20-minute timeout, and transient network/5xx failures are abandoned immediately, preventing later sources from refreshing. Use an `AbortSignal.timeout` (or equivalent) and bounded retries for network/5xx responses.

- `scripts/snapshot.mjs:70-72` and `.github/workflows/snapshot.yml:26-41` — severity: medium — the snapshot process exits successfully whenever at least one of the three jobs succeeds. A failed source therefore leaves its old snapshot stale while the workflow is green and can still commit/deploy the other sources, with no failure signal. Return nonzero for any failed source (while retaining successful files) or publish an explicit per-source failure status.

- `src/features/registry/useRegistry.ts:77-91` and `src/features/registry/RegistryLog.tsx:90-99` — severity: medium — registry errors are stored only in per-chain button `title` text. If all initial calls fail, `loading` becomes false and the panel says “No registrations in range” while its live dot remains active; touch users have no visible error. Render an explicit error/unavailable state and make liveness depend on a successful chain, while still retrying failed chains.

## Low

- `src/features/registry/RegistryLog.tsx:21-34,51-60` — severity: low — the expandable row is a clickable `motion.li` with no focusability, button role, keyboard handler, or `aria-expanded`, so keyboard and screen-reader users cannot open descriptions. The metadata link at line 56 also bubbles into the row and toggles it. Use a disclosure button with an accessible relationship and stop link events (or keep links outside the disclosure control).

- `src/components/Pagination.tsx:25-36`, `src/features/registry/RegistryLog.tsx:74-84`, and `src/features/payments/PaymentsPanel.tsx:61-78` — severity: low — `addedSinceLeaving` is based only on list length. Once the registry reaches its 200-event cap, new inserts evict old rows and the length stays 200, so the “new” banner remains zero; the payments panel never renders the counter at all. Page contents can shift silently while the reader is on page 2. Track a monotonic insertion/head key and provide the new-items affordance for both live lists.

- `src/features/registry/RegistryLog.tsx:87-91`, `src/components/ThemeToggle.tsx:9`, and `src/components/Pagination.tsx:52-64` — severity: low — chain filters do not expose pressed state, the theme button's accessible name is hard-coded English and does not expose the current state, and the pagination landmark label is hard-coded English. In non-English locales, screen-reader users receive untranslated controls and no selection/current-page semantics. Localize the labels and add `aria-pressed`/`aria-current` where applicable.

- `src/lib/format.ts:24-29` — severity: low — `atob` returns a byte string, which is passed directly to `JSON.parse`. Base64 `data:` URIs containing UTF-8 names or descriptions are consequently rendered as Latin-1 mojibake, especially for CJK metadata. Decode the base64 bytes with `TextDecoder` before parsing.

- `public/404.html:7-10` — severity: low — the fallback derives the app root from the first path segment. With the documented custom-domain setting `VITE_BASE=/`, an unknown `/foo` path redirects to `/foo/` rather than `/`, so the 404 page loops instead of returning to the app. Generate the fallback with the configured base or handle `/` separately.

- `vite.config.ts:69-73` — severity: low — the Google Fonts stylesheet cache uses `StaleWhileRevalidate` without an expiration policy. Each changed stylesheet URL/query can leave another entry in `aeo-google-fonts-styles` indefinitely, unlike the bounded font-file cache. Add a small `maxEntries`/`maxAgeSeconds` policy or constrain the route to the one known URL.

- `src/features/payments/usePayments.ts:97-103` and `src/features/registry/useRegistry.ts:83-110` — severity: low — cursors advance through the current head with no confirmation lag, block-hash tracking, or recent overlap. A chain reorg after a scan leaves removed payments/registration events in state or misses replacement logs. Scan a finalized head with a small overlap and reconcile by block hash/event key.

- `src/features/registry/useRegistry.ts:33-37` — severity: low — `URIUpdated` supplies an `updater`, but it is stored in the field named `owner` and rendered as the row's address. If an approved operator updates the URI, the event actor is not the NFT owner. Rename the field to `actor`/`updater` or resolve the actual owner separately.

- `src/features/payments/usePayments.ts:104` and `src/features/registry/useRegistry.ts:88,111` — severity: low — error handlers cast arbitrary caught values to `Error` and immediately call `.message.split`. A non-`Error` rejection can throw while handling the original RPC failure and hide the real error. Normalize with `e instanceof Error ? e.message : String(e)`.

- `src/lib/theme.ts:27` and `package.json:17,24` — severity: low — `ink` has no call sites, and `gsap`/`wagmi` have no imports in the source; they add maintenance/install weight without affecting the current bundle. Remove them or add the intended usage.
